Key terms

Identity Provider

The system that authenticates the user, such as Entra ID, Okta, Ping, or Auth0. [web:50][web:63]

Service Provider

The app that trusts the IdP and grants access after validation. [web:49][web:55]

Assertion / Token

SAML uses a signed assertion; OIDC uses an ID token to convey identity. [web:55][web:63]

Session

The app session created after the token or assertion is accepted. [web:50][web:58]

MFA

Extra verification such as authenticator app, passkey, or biometric step. [web:71][web:74][web:96]

RelayState / Redirect

Used to return the user to the right app path after sign-in. [web:80][web:84]

Audience / ACS

Validation targets that help the app confirm the message is meant for it. [web:80][web:95]

Clock Skew

Time difference between IdP and SP that can break assertions if not handled. [web:91][web:102]

Good example: an engineer clicks “Sign in with SSO” on Jira, gets redirected to the company IdP, completes MFA, and then returns to Jira already logged in. The same browser session can often be reused for other enterprise apps without another password prompt. [web:50][web:81][web:85]

Identity Provider

The IdP is the trust anchor. It stores the user directory or connects to it, authenticates the user, and issues the signed SAML assertion or OIDC token that the application will verify. [web:50][web:55][web:63]

Phishing or credential theft One stolen login can unlock many apps if MFA is weak or absent. [web:68][web:69][web:86]
Misconfigured federation Bad metadata, wrong redirect URIs, or broken signature validation can cause unauthorized access or outages. [web:71][web:102]
Single point of failure If the IdP is down, access to many connected systems may stop. [web:72][web:86]
Over-broad access Weak role mapping and no reviews cause privilege creep and excessive access. [web:72][web:70]

Best practices checklist

1. Enforce strong MFA Use MFA for all users and especially for admins and sensitive apps. [web:71][web:74][web:96]
2. Validate federation carefully Check signatures, issuer, audience, redirect URIs, metadata, and time validity windows. [web:55][web:58][web:91][web:102]
3. Apply least privilege Map access to roles or attributes, then review and remove access regularly. [web:67][web:72][web:70]
4. Monitor and log Watch for unusual logins, risky sessions, and access anomalies. [web:72][web:74]
5. Automate lifecycle Provision and deprovision quickly so old access does not remain active. [web:70][web:72]

Protocol notes

SAML is common for enterprise workforce SSO and returns XML-based signed assertions, while OIDC is a modern authentication layer that returns tokens such as an ID token. Both rely on browser redirects and a configured trust relationship between the IdP and the app. [web:55][web:63][web:82][web:89]

A useful mental model for engineers is: the app asks “who are you?”, the IdP proves it, and then the app asks “what are you allowed to do here?”. [web:50][web:85]
